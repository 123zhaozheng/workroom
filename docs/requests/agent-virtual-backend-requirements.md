## 1. 给实施 Agent 的任务

请完成一次围绕 Agent 文件访问、长期记忆、成果交付和代码执行的整体重构。保留 pi-durable 作为运行内核，为它构建 TypeScript 虚拟文件后端和统一工具层。

Agent 应当通过少量通用工具访问 `/skills`、`/memory`、`/library`、`/uploads`、`/work`，由路径决定实际后端。系统提示解释目录用途；后端实施真实权限、路径路由和操作规则。

请先检查已有实现与调用方，形成简短的变更清单，然后按纵向链路落地代码、迁移和验证。交付完整可用的功能，不要只改工具名、只改提示词、只隐藏版本标签，或只提交一份设计说明。正常实现选择可自行决定；涉及真实历史数据丢弃时，先给出可核查的迁移与备份方案。

## 2. 已经确认的产品决定

1. 统一虚拟文件路径；Agent 不再需要根据存储类型选择 `sandbox_read_file`、`file_read`、`memory_save` 等不同工具。
2. 长期记忆以 Markdown 文件为唯一内容事实来源，采用 `MEMORY.md` 索引加分类文件。允许 Agent 主动整理有依据的稳定偏好、背景和长期事实；用户能在前端直接编辑同一份内容。
3. 文件库只展示明确交付给用户的成果。中间文件、日志、用户聊天上传附件、浏览器截图等不自动成为交付物。
4. 提供 `present_file` 工具：支持 `/work` 文件和 HTTP(S) URL；成功后保存文件库文件，并在聊天中显示可预览、可下载的文件卡片。
5. 文件库按会话分目录。同一会话同名交付覆盖当前文件，保留稳定文件身份；不建设用户可见或新业务层面的文件版本体系。
6. “移动到 work”最终定义为复制：提供 `copy_to_work`，复制后保留来源。
7. 代码执行统一到完整沙盒后端，移除 Agent 自动选择浏览器执行的产品路径。前端不再要求用户理解“浏览器轻量执行”和“云端执行”的区别。
8. 默认仍可按需创建沙盒。文件查询、记忆读取、技能说明读取不应该为了执行这些操作而启动远端沙盒。

## 4. 统一虚拟命名空间

### 4.1 路径与能力

所有 Agent 可见路径使用 POSIX 绝对路径。相对路径统一相对当前会话 `/work` 解析；内部对象存储 key、宿主机 dataDir、提供方物理路径不直接成为 Agent 接口。

| 虚拟路径 | 含义与归属 | 通用读取/搜索 | 通用写入/编辑 | Shell 执行 |
| --- | --- | --- | --- | --- |
| `/skills/<slug>/` | 当前执行身份有权使用的技能包 | 支持；包含 SKILL.md、scripts、references 等 | 用户自有可写技能允许；安装包/系统/组织只读内容拒绝 | 先复制所需技能到 `/work` 再执行 |
| `/memory/` | 当前用户的个人 Markdown 长期记忆 | 支持，按身份隔离 | 支持，前端与 Agent 操作同一内容 | 不在此执行；需要处理文件时显式复制 |
| `/library/<会话目录>/` | 已交付成果，个人或明确授权的会话范围 | 支持列表、读取、搜索；二进制按类型处理 | 内容写入统一走 `present_file`，普通 write/edit 返回明确指引 | 复制到 `/work` 后执行处理 |
| `/uploads/<消息或附件标识>/<文件名>` | 用户在聊天上传的原始附件 | 支持，沿用附件与会话 ACL | 原件只读 | 使用 `copy_to_work` 获取工作副本 |
| `/work/` | 当前会话完整沙盒中的工作区 | 支持 | 支持 | 唯一 exec 后端 |

“接口统一”不等于每个目录都允许所有操作。`ls` 的结果应包含节点类型、大小、修改时间和实际可用操作；拒绝操作由后端执行，不能仅靠提示词约束。

`ls('/')` 只返回当前上下文可访问的虚拟根。未知根返回结构化错误，不回退到宿主机真实文件系统。跨目录搜索保持虚拟路径，不泄露真实存储位置。

### 4.2 身份、范围与路径稳定性

- 每次运行持久绑定 `orgId`、`userId`、`spaceId`、`conversationId`、必要的 projectId，以及本次操作来源。不得从最后一条历史消息猜执行身份。
- `/work` 对当前会话固定；主 Agent 和子 Agent 各有确定的工作区归属，不能用父路径字符串推断权限。需要共享文件时显式传递/复制。
- `/memory` 在用户私有会话映射到该用户私有内容。共享项目对话不得自动注入任何人的个人记忆，也不得把个人记忆通过工具结果暴露给其他成员。
- 已存在的项目/组织记忆保留原 ACL，迁移为独立 Markdown 作用域；需要在统一视图中访问时可使用 `/memory/shared/project/<projectId>/`、`/memory/shared/org/`。它们不并入个人索引，个人记忆也不迁入共享作用域。
- `/library` 只列出当前身份有权访问的会话成果目录，不把“同组织”视为可读取所有人的文件。
- 会话文件夹内部按稳定 conversationId 绑定，展示名称由会话标题生成，例如 `/library/咖啡店销售分析--c123/`。标题后续变更时不能使原路径、卡片和下载失效；可固定创建时路径，UI 显示当前标题。
- 权限撤销应在后续工具调用、预览和下载中生效。

## 5. 后端与工具层

### 5.1 后端结构

建立一个路由器和职责清楚的后端：SkillsBackend、MemoryBackend、LibraryBackend、UploadsBackend、WorkBackend。按规范化后的路径进行最长前缀匹配，统一返回文件元数据与错误。

可以复用项目现有存储服务；“虚拟后端”并不要求把所有内容改成数据库，也不要求所有目录真实挂载进沙盒。读取一个数据库/对象存储中的文件，不能为了模拟目录而启动容器。

优先核对项目实际安装版本的 pi-durable `FileSystem`/`ExecutionEnv` 与原生 `read/write/edit/bash` 工具，能复用的适配复用；不满足统一契约的地方实现薄工具层。不要为复用默认 Node 环境而让 exec 意外在应用宿主机执行，也不要引入 Python LangGraph 来替换现有内核。

### 5.2 对 Agent 的统一工具

建议注册以下工具，最终命名可在保持一致语义的前提下微调：

| 工具 | 必须具备的行为 |
| --- | --- |
| `ls(path)` | 跨虚拟目录列目录、节点元数据、分页；支持根目录发现 |
| `read(path, offset?, limit?)` | 文本分段读取；图片和可解析文档返回合适内容；二进制不伪装成 UTF-8 |
| `write(path, content, expected_etag?)` | 创建/覆盖允许写入的文本文件，自动创建允许的父目录，按实际范围实施权限 |
| `edit(path, old_text, new_text, expected_etag?)` | 精确替换；匹配不到或出现歧义时明确失败，避免覆盖并发编辑 |
| `search(path, query, mode?)` | `mode=name/content`，统一查找文件名或文本内容，结果分页/限量，保持虚拟路径 |
| `remove(path)` | 只删除允许范围内的文件；文件库删除落实为撤回可见成果，技能只读内容不可删；目录递归删除必须显式参数 |
| `exec(command, cwd?, timeout_ms?)` | 在 `/work` 对应的完整沙盒运行 Shell 命令，支持流式输出、退出码、超时和取消 |
| `present_file(source, name?, description?)` | 把 `/work` 文件或 HTTP(S) URL 保存为会话成果，并产生文件卡片 |
| `copy_to_work(source, destination?, overwrite?)` | 从允许读取的虚拟文件或 URL 复制到当前会话 `/work`，保留原件，不产生文件卡片 |

工具结果应同时满足模型和 UI：可读文本、稳定结构化字段、明确错误码；文件大小、结果长度和目录数量使用已有配额/限制，不能无限返回。

旧工具名在新会话中不再注册和出现在提示词。历史记录仍能正确渲染；已经持久化的旧任务由兼容执行适配器处理到终态，兼容层不向新 Agent 再暴露一套工具。不要直接重命名任务 kind/version 导致旧 pi-durable 任务无法解析。

`codemode` 如保留，只负责在受限运行时编排工具调用。它不再作为第二种用户代码计算后端；脚本需要 Python/Shell/系统依赖时仍调用统一 exec。MCP、搜索、浏览器控制等独立业务工具继续存在，本次收敛的是文件访问与代码执行工具。

## 6. Markdown 记忆

### 6.1 内容组织

个人记忆采用以下起始约定，不需要预先创建大量空文件：

| 路径 | 内容 |
| --- | --- |
| `/memory/MEMORY.md` | 简短核心摘要、分类索引、主题链接 |
| `/memory/preferences.md` | 语言、沟通方式、输出格式、工作习惯等稳定偏好 |
| `/memory/profile.md` | 用户明确提供的身份、职业、长期背景 |
| `/memory/facts.md` | 跨会话有用的稳定事实和长期约束 |
| `/memory/projects/<slug>.md` | 用户私有的项目背景、已确认决定、持续目标；不自动等于共享项目资料 |

本轮不默认保存逐日聊天流水、逐条工具输出和完整对话转录到记忆。确有稳定的新主题时再加文件，并更新索引。

推荐内容格式如下，示例中的偏好只展示结构，不是要写入真实用户的初始记忆：

```markdown
# 偏好

## 沟通与语言
- 默认使用简体中文。
- 先给结论，再按需展开原因。

## 工作方式
- 更偏好可以直接执行或交付的结果。
```

```markdown
# 长期记忆

## 核心摘要
- 沟通方式：简体中文，优先给出结论。

## 主题索引
- [偏好](preferences.md)：语言、输出方式与工作习惯。
- [个人背景](profile.md)：已确认的身份和长期背景。
- [长期事实](facts.md)：稳定事实与约束。
```

使用 UTF-8 Markdown、清楚的标题、短条目和可读链接。无需把自然语言记忆变成大量 JSON/YAML 属性；更新时间、修改人、来源会话等可以存在轻量元数据/审计中。内容必须能不依赖专用 UI 直接阅读。

### 6.2 主动维护规则

- 用户已允许 Agent 主动整理长期记忆，不要求每次写入都弹审批。
- 记录有对话依据的稳定偏好、明确纠正、长期事实和持续项目背景。临时任务参数、一次性文件内容、Agent 推测不直接变成长期事实。
- 更新同一偏好时替换过时表达，合并重复内容，避免在不同文件中同时保留互相矛盾的现行结论。
- 用户修改或删除的内容优先。Agent 不得从旧缓存或旧 DB 条目自动恢复已删除记忆；删除应同步使索引与派生检索失效。
- 不把第三方网页或技能文档中的指令当成用户偏好写入。记忆内容是背景信息，不授予工具、账号或系统权限。
- 文件内容是唯一事实来源。可有全文搜索索引、etag、缓存和审计，但它们是可重建派生数据，不得另外维护一份会冲突的记忆正文。

### 6.3 注入与前端

- 每次新运行获取当前有权使用的 MEMORY.md 核心摘要与索引，并提供按需读取主题文件的指引；不要每轮把全部主题文件塞入系统提示。
- 注入设置明确可配置的长度预算，初始可按不超过 6,000 字符处理。超限需有截断提示和主题文件路径，不能修改或截断磁盘原文来迎合预算。
- 前端或 Agent 更新后，下次模型请求读取最新可用内容；同一次正在流式生成的请求不强行重写上下文。
- 前端“记忆”页面展示分类列表、Markdown 阅读和编辑，支持保存、删除、新增主题、查看最近修改时间。编辑的是同一份文件内容，不是数据库卡片的另一份复制。
- 前端保存与 Agent edit 使用相同服务和并发控制。etag/内部修订标识只用于防止覆盖，不是产品文件版本功能；冲突返回可理解的提示，不静默丢失用户修改。
- 更新过程中保证文件写入原子性；删除主题同时处理索引。现有私有、项目、组织记忆按原权限迁移，不混合范围。

## 7. 成果文件库与 present_file

### 7.1 唯一交付边界

“文件生成了”和“文件交给用户了”是两个动作。

- `write('/work/...')`、exec 生成文件、读取 URL、浏览器截图、后台任务产生输出，都不自动在聊天中显示成果卡片，也不进入默认文件库列表。
- 聊天上传只进入 `/uploads`：原消息正常显示附件，不计入“Agent 生成文件”数量，不自动出现在成果文件库。
- Agent 判断某个结果应交付后，调用 `present_file`；只有保存成功的交付才产生 `file.presented` 记录及文件卡片。
- `/library` 是这份已交付成果集合的虚拟文件视图。入库、卡片、列表与下载引用同一 fileId，不能分别维护三份状态。
- 工具失败、文件不存在、远端同步失败、URL 下载失败时，不显示成功卡片，不用一个空文件冒充成果。

### 7.2 来源与保存

最小必需输入：

```json
{"source":"/work/out/咖啡店销售分析.xlsx","name":"咖啡店销售分析.xlsx"}
```

```json
{"source":"https://example.com/report.pdf","name":"研究报告.pdf"}
```

- `/work` 来源读取当前工作区真实文件；远端执行时先在同一工作区锁下完成必要的同步/读取，不能拿宿主机旧副本冒充当前结果。
- URL 来源默认下载实际字节并保存，不能只保存一个随时过期的外链就宣称文件已归档。复用项目网络出口与 URL 校验，实现重定向检查、超时和流式大小限制；不把服务端模型密钥或浏览器登录 Cookie 自动带到外部 URL。
- 文件名由显式 name、可信 Content-Disposition 或 URL 路径确定，并规范化；判断 MIME 与实际内容，复用当前预览能力。
- 文件落到当前会话成果目录，无需 Agent 自己拼会话目录。禁止输入任意他人目录充当发布目标。
- 保存完成再返回稳定的 fileId、虚拟路径、名称、MIME、size、previewUrl、downloadUrl，以及 `created/updated/unchanged` 状态。
- 发布会话无权访问的源文件必须拒绝；个人记忆与技能源文件不因为提供了一个路径就可以自动泄露到共享会话。

建议结果形状：

```json
{
  "status":"created",
  "fileId":"file_...",
  "path":"/library/咖啡店销售分析--c123/咖啡店销售分析.xlsx",
  "name":"咖啡店销售分析.xlsx",
  "mime":"application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
  "size":8294,
  "previewUrl":"/api/files/file_.../preview",
  "downloadUrl":"/api/files/file_.../download"
}
```

### 7.3 同名覆盖、重试与并发

- 唯一业务键至少包含当前租户/空间、会话成果目录与规范化后的文件名。同名覆盖的 fileId 和下载入口稳定，更新内容、大小、MIME、hash 和时间；不同会话的同名文件互不覆盖。
- 同一次工具调用重试不重复保存、不重复插卡片；另一次调用交付同名文件按用户已确认的规则覆盖，不自动增加 `v2` 或新建同名行。
- 用稳定工具调用标识记录交付回执。崩溃发生在文件保存与 pi-durable 工具结果之间时，恢复能找到已保存的结果，而不是再创建一份文件。
- 较老调用的重放不得把后来成功交付的新内容覆盖回去。并发交付需要确定顺序及每目标串行化/条件更新。
- 文件内容与交付记录/事件保持可对账：优先在文件业务数据库的同一事务中保存元数据、调用回执和待推送事件，pi-durable 工具重放据此恢复。不要声称两个独立 SQLite 数据库天然具备原子事务。
- 新数据模型不再以 file_versions/版本链为核心。内容寻址 Blob、hash、内部 etag 可以保留作实现细节，不变成版本产品。

### 7.4 聊天卡片与文件库 UI

用户截图表达的是“成果文件卡片”，不是强制把 XLSX 单元格直接展开成聊天表格。

- 卡片保留文件类型图标、文件名、文件类型、大小、下载按钮；点击打开现有预览面板。
- 删除卡片的 `v1`，同时移除文件列表、文件详情、预览面板和工具结果描述里的成果版本号、版本选择器、历史版本入口。
- 同名覆盖后按 fileId 更新已有卡片与列表；旧会话消息里的该文件卡片也解析到当前文件。用户已接受此处不提供旧内容回看。
- 预览缓存按内容 hash/etag 失效；覆盖后不能仍显示旧缩略图、旧表格或旧下载字节。
- 聊天中“生成 N 个文件”只统计明确交付并去重后的成果。上传附件、临时文件、未发布截图不增加 N。
- 默认文件库页面只列成果，按会话组织。仍可在会话中看到原始上传附件，它们不因为没有进入成果文件库而消失。
- `read`、`ls` 和 `copy_to_work` 返回的普通 file 元数据不能被前端自动识别成“新成果卡片”；渲染以明确交付协议为准。
- 用户从前端删除成果，相关目录项和卡片变成已移除状态，不能留下仍可下载的悬空链接。

## 8. copy_to_work 与完整沙盒

### 8.1 复制语义

```json
{"source":"/uploads/msg_123/销售.xlsx","destination":"/work/inputs/销售.xlsx"}
```

```json
{"source":"/library/销售分析--c123/报告.xlsx","destination":"/work/inputs/报告.xlsx"}
```

```json
{"source":"/skills/report/scripts/analyze.py","destination":"/work/tools/analyze.py"}
```

- 支持有权读取的虚拟文件和 HTTP(S) URL，目标限定当前会话 `/work`；保留来源，不做真正移动。
- 技能需要关联资源时，允许显式递归复制技能目录；不默认复制全部技能、全部记忆或整个文件库。
- 返回实际可用于 exec 的 `/work/...` 路径、大小/hash 和状态。写入前检查配额，远端文件实际可用后再宣称复制完成。
- 相同调用重试可复用其复制结果；不同源碰到已有同名目标时默认返回冲突，除非明确 `overwrite=true`。不可默默破坏用户或 Agent 的工作文件。
- 复制不发布文件、不产生卡片、不改变原件。复制的技能文件可在 `/work` 修改，源技能权限不受影响。

### 8.2 唯一执行入口

- Agent 只看到一个 exec，它运行完整沙盒里的 Shell：可启动 Python/Node、安装允许的依赖、处理文件和运行测试，能力取决于配置的沙盒。
- 删除正常 Agent 流程中的浏览器 JS/Pyodide 自动选路、浏览器标签页任务领取、自动升级到云端重跑，以及前端“本地浏览器/云端”二选一入口。正常网页应用自己的 JS 和浏览器控制工具不在删除范围。
- 复用 Docker/namespaces/远程提供方驱动接口，按部署选择一个沙盒后端；不得因为配置不可用而把任意命令退回应用宿主机裸执行。
- `/work` 在 exec 环境中必须是真实可访问的稳定路径，不能仅靠替换命令字符串中的 `/work`。通过镜像、挂载或受控别名适配提供方；未满足路径契约的提供方应明确报告不可用。
- 虚拟 `/memory`、`/library`、`/uploads` 不必真实挂载进沙盒。要用 Shell 处理这些文件先 copy_to_work；普通 read/write 则直接走各自后端。
- 真实沙盒仍需要系统目录和运行时；“exec 路由到 /work 后端”不等于 Shell 天然只能读取 cwd。隔离靠实际沙盒与挂载权限，不靠提示词或命令字符串黑名单。
- 对 `/work/a.txt` 的 write/read/edit 与 exec 对同一文件的操作必须可相互观察。定义唯一工作区事实来源及同步边界，避免虚拟后端、宿主机缓存、远端实例各自拥有不同“最新文件”。
- `/work` 默认每会话独立、同会话跨轮复用。共享项目目录另按明确 ACL 挂载，不把所有会话合并到一个可任意读取的用户沙盒。
- `ls/read/write` 操作只读虚拟后端时不拉起沙盒；首次 `/work` 使用或 exec 按需创建。明确的编程/分析请求可提前准备；预热和 exec 必须复用相同获取锁，不得创建重复实例。
- 保留现有暂停、恢复、回收、输出上限和取消能力。中断的普通 Shell 命令默认不可自动重放；进程重启后向模型说明执行结果未知，不能静默再跑一次可能有副作用的命令。

## 9. 系统提示词契约

实现稳定的目录说明 section，使用当前运行上下文生成，不注入宿主机路径。示例：

> 你可以使用统一文件工具浏览虚拟文件系统。`/skills` 是当前可用技能，先读取相关 SKILL.md，系统安装技能只读；`/memory` 是按权限提供的 Markdown 长期记忆，MEMORY.md 是索引，你可以主动维护有依据的稳定信息；`/uploads` 是用户原始附件，只读；`/library` 是已交付成果，按会话分目录；`/work` 是当前会话的完整沙盒工作区，可执行命令和存放中间文件。需要用命令处理虚拟目录中的文件时，先用 copy_to_work 复制到 /work，保留原件。生成文件不等于交付文件：只有调用 present_file 成功，文件才进入文件库并显示给用户。不要主动展示上传附件、临时文件和过程日志。同一会话同名交付覆盖当前文件，不创建版本。

提示还应说明：当前身份能写哪些目录；exec 的默认 cwd、可用后端与实际限制；MEMORY.md 的索引位置。后端不可用时如实返回，不让模型误以为已经运行或交付。

## 10. pi-durable 集成要求

- 保留 pi-durable 对会话、模型生成、工具任务、submission、恢复的所有权。不要再写一套独立 Agent 循环。
- 执行身份、工具允许列表、目录能力、凭据与预算均来自当前运行上下文。继续/重新生成必须明确当前操作人，不能继承历史作者权限。
- 主模型及每个 fallback 模型分别检查权限；文件工具通过同一身份解析，不绕过现有 ACL。
- read/ls/search 可按只读策略重试；write/edit/remove/present_file/copy_to_work 只有具备明确幂等或条件写语义时才声明 replay-safe；exec 默认 replay-unsafe。
- 审批、子 Agent 和后台任务终止后同步清理相关状态。不要让早已结束的任务继续显示待审批/运行中。
- 不把持久化的“复制/发布待处理状态”仅保存在进程内 Promise/Map。处理工具结果提交前后崩溃的窗口，重启后根据回执恢复。
- 实施前核对真正发布并安装的 pi-durable 接口。调研基准的官方 main 中，ToolPark、defineSignal 等仍在 Unreleased；不要把它们写成 1.5.0/1.5.2 已提供的接口。若选择升级或固定其他提交，明确依赖和迁移影响。

## 11. 迁移与范围控制

### 11.1 必须迁移

1. 现有 DB 记忆转 Markdown，按原 scope、owner 和 ACL 分开；重复/冲突记录给出可追踪的迁移报告。个人记忆文件与原 memories 长期文件目录明确区分、合并入口，不能静默丢失非 Markdown 文件。
2. 现有已交付文件迁移为“当前文件”。旧版本只挑最新有效内容作为新成果；旧下载引用在过渡期可解析或明确跳转。
3. 历史上传附件进入 uploads 视图；历史明确交付物进入 library。可利用来源工具、origin 和旧 artifact 记录判定，不确定的不要直接删除或自动公开。
4. 所有前后端 versionId/版本列表依赖审计。知识库文档引用、技能包版本、pi-durable 检查点和内部恢复快照不等于“AI 成果文件版本”；不因本需求把这些独立机制一起删掉。
5. 旧工具历史渲染与未完成任务过渡处理。新会话只有一套通用文件工具，不长期并列两套 Agent 接口。
6. 移除浏览器执行链路并清理不再使用的包、路由、类型、设置和文案；对已有待领取浏览器任务给出终态，不能自动在另一环境重跑。

无需为新成果建立版本历史；迁移前备份、用于防并发覆盖的 etag、运行恢复信息可以作为内部实现保留。不要借本次重构重写身份系统、模型网关、知识库检索、全部技能市场或沙盒 SDK。

### 11.2 建议实施顺序

1. 统一路径协议、身份上下文、后端路由与基础文件工具。
2. 跑通上传 → copy_to_work → exec → present_file → 文件库与卡片的完整链路。
3. 接入 SkillsBackend 与 Markdown MemoryBackend，完成前端记忆编辑和注入。
4. 收敛文件数据模型与预览/下载，完成同名覆盖与崩溃重放回执。
5. 删除浏览器执行分支、旧工具新注册和过时文案，完成历史数据及任务兼容。
6. 运行验收，输出变更清单、迁移结果、验证结果和真实未验证项。

## 12. 验收用例

以下用例优先做真实服务层/工具层集成验证，模型可用本地模拟 provider；无需消耗真实付费模型。远端沙盒可用契约替身，但至少一种可用的真实隔离后端应验证执行链路；不可用时明确记录，不能把跳过写成通过。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| V01 | `ls('/')` | 仅列当前身份可用的虚拟根，包含正确能力，无真实宿主路径 |
| V02 | 读技能和记忆 | 不创建/连接远端沙盒；分页、路径和权限正确 |
| V03 | 写技能 | 系统技能拒绝，用户有权维护的技能成功，其他用户不可见 |
| V04 | 个人记忆跨会话 | 新会话读到当前 MEMORY.md 与相关主题，Agent 可主动更新有依据的偏好 |
| V05 | 前端编辑记忆 | 保存后 Agent 下一次模型请求读取新内容；不再注入旧 DB 文本 |
| V06 | 并发修改记忆 | 用户编辑与 Agent edit 冲突可见，用户修改不被静默覆盖 |
| V07 | 记忆删除 | 索引和检索同步，后续不会从旧索引/旧 DB 自动复活 |
| V08 | 聊天上传 Excel | 原消息显示附件，uploads 可读；library、成果卡片和生成文件计数不增加 |
| V09 | 复制到 work | 原附件/成果保留，沙盒实际可读工作副本，无卡片 |
| V10 | 统一文件视图 | write 后 exec 可读；exec 写入后 read 可读；远端同步失败明确失败 |
| V11 | 执行与中间产物 | 生成日志、脚本、CSV、图片等不自动发布，不显示成功成果卡片 |
| V12 | 工作文件交付 | present_file 成功后，聊天卡片、library 虚拟目录、文件库列表、预览和下载一致 |
| V13 | URL 交付 | 下载并保存真实字节；URL 过期后已保存文件仍可下载；错误/超限无成功卡片 |
| V14 | 同名再交付 | 同一 fileId 更新，卡片和缓存更新，无 v2/重复行；其他会话同名文件不受影响 |
| V15 | 工具重放 | 保存后、工具结果提交前强杀进程，重启后不重复交付；旧调用重放不覆盖更新内容 |
| V16 | 权限隔离 | 路径穿越、symlink 越界、他人 memory/library、共享对话读取个人记忆均拒绝 |
| V17 | 不同操作发起人 | 编辑者重新生成不会借原作者模型/文件权限，fallback 仍按当前身份检查 |
| V18 | 统一 exec | 浏览器关闭不改变执行后端；代码只在配置沙盒执行，取消能终止或报告未知状态 |
| V19 | 目录路径稳定 | 支持的提供方中 `/work` 在命令内真实可访问；会话改名不破坏成果路径和下载 |
| V20 | 历史迁移 | 最新有效成果、原附件、Markdown 记忆 scope 完整；旧会话能读，未完成旧任务能收尾 |
| V21 | 截图对应 UI | 文件名/类型/大小/预览/下载具备；无版本号；生成数量只含交付文件 |
| V22 | 文件库删除 | 虚拟目录与前端同时移除，旧卡片显示已删除，不继续泄露下载内容 |
| V23 | 后台任务/截图来源 | 非 present_file 的普通工具结果不会触发成果卡片或自动入库 |
| V24 | 沙盒生命周期 | 纯记忆/技能读取不启动沙盒；准备与 exec 并发不重复创建；恢复后不盲目重放命令 |

实施结束必须报告：已完成的链路、迁移策略、实际运行的检查、真实后端验证范围、剩余风险。涉及数据库、Agent 工具、前端卡片的改变均需闭环，不把“后端有接口、前端以后接”当作完成。
