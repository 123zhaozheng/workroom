# 在线工作 Agent：三项目源码研读与产品功能基线

研究日期：2026 年 11 月 9 日  
产品方向：浏览器内运行、默认界面简洁、能够持续完成工作的通用 Agent。  
目标：以 PigeonAgent 与 DEEIX-Chat 为重点参考，以 LambChat 为能力基线，形成覆盖更完整、交付更可追溯、企业使用更顺畅的产品。

## 2. 产品定位应当这样定

用户打开浏览器，说清楚想完成的事情，Agent 按需使用知识、文件、工具和执行环境，持续推进，最终交付可以预览、下载、修改和复用的成果。

适用场景包括研究、资料整理、写作、数据分析、网页任务、内容制作、业务协助和自动化。首页不预设为经营分析、报表制作或某一类行业应用。

日常体验以对话为中心。知识库和文件库有清晰入口；执行细节、审批、成果预览在需要时出现。统计、组织管理和平台配置进入独立页面。

终端默认只承担网页交互与必要的预览工作，模型推理、代码执行和浏览器自动化由服务端或受控环境承担。用户完成普通工作不应被要求先安装客户端、Python、Node.js 或本地依赖。

## 3. 三个项目分别值得学什么

### 3.1 PigeonAgent：对话界面和执行反馈

值得参考的重点：

- 普通对话、执行过程、附件与成果在同一条会话中形成连续体验。
- 工具输出和推理展示可以逐层展开；确认卡片直接嵌入当前任务。
- HTML 预览按需打开到右侧，窄屏改用侧面抽屉。
- 发布文件时落入统一文件记录，并向前端发出成果事件。
- 对话树、上下文压缩、事件回放、跨 worker 取消等能力已经进入实现层。

前端为 Vue 3、Tailwind CSS v4、shadcn-vue / Reka UI，部分 AI Elements Vue 组件源码；流式内容使用 markstream-vue、Shiki。品牌背景和输入框过渡有作者自己的实现。

需要区分：对话重连后能接回事件流，与执行 worker 崩溃后能安全恢复任务，是两个不同验收项。本次没有把前者当作后者的完整证明。

参考代码：P01—P06。

### 3.2 DEEIX-Chat：知识、模型与企业平台能力

值得参考的重点：

- 文件库、知识库、指令库分别建立实体与页面。
- 个人知识库与管理员内置知识库有明确访问判断。
- 检索过程记录命中片段、失败原因、回退情况和证据信息。
- MCP 调用有参数校验、启用范围、结果预算、调用记录与计费关联。
- 平台模型与上游渠道分离，并配置模型路由、协议适配和能力。
- 账号、身份源、用量、计费、日志和管理后台覆盖较广。
- 前端静态导出，生产时可由 Go 服务托管；文档提取和 OCR 可接入可选处理服务。

前端为 React、Next.js、Tailwind、shadcn/ui，结合 Radix / Base UI、Streamdown、Motion、Recharts。仓库中有 Animate UI 图标源码与少量 React Bits 视觉组件。

两个容易被名字掩盖的边界：

1. 本次阅读的知识库模型明确包含 `user` 与 `builtin` 两种范围，不能据此直接推导出已经支持部门级、项目成员级权限。
2. 当前选中 Skill 的链路会加载 SKILL.md 内容作为上下文；代码明确说明，这不自动授予脚本、系统命令、后台任务或未选择工具的执行权限。因此“Skill 文本加载”和“完整可执行技能生命周期”应分别验收。

参考代码：D01—D08。

### 3.3 LambChat：必须认真覆盖的 Agent 基线

它已经覆盖了许多容易被当成“新增卖点”的能力：

- quick / search / team 类型 Agent、子 Agent、技能市场、人格配置和记忆。
- 多供应商模型、系统／用户 MCP、沙箱及交付物文件库。
- 定时任务、后台执行、通知渠道、Web 与其他客户端。
- 常驻助手已经存在实现：类型包含 assistant、group、chief。
- 助手任务有完成、验收、需修改等状态。
- 插话调整、人工介入、恢复锁与重试上限已经有代码。
- 项目整理、项目分享、用量、角色与账号管理也已有实现。

特别是，不能把“常驻助手”“任务做完后验收”“后台任务恢复”“项目分享”直接列成我们独有的功能。

同时应区分几个概念：

- 多用户账号与 RBAC，不自动等于完整的企业组织树和租户隔离验收。
- Agent 小队，不自动等于真实同事共同编辑一个项目。
- 项目公开分享，不自动等于成员级、可编辑、可撤销的协作空间。
- 记忆检索，不自动等于具备文件版本、权限同步及引用定位的知识库治理。

参考代码：L01—L09。

## 5. 我们的目标产品：18 个功能模块

这些是能力模块，不是 18 个常驻菜单。每个模块列出 3 条关键验收要求，共 54 条。

### M01 通用对话工作区

范围：普通问答、研究、文件任务、内容制作、会话历史、搜索、分支、编辑、再生成、分享与导出。

- **M01-A**：同一界面完成纯聊天、带附件和带知识引用三类请求，不要求用户先选择复杂工作流。
- **M01-B**：编辑、再生成产生可辨识的版本或分支，不覆盖用户需要保留的结果；刷新后能找回。
- **M01-C**：长回答、代码、表格、公式与引用可阅读、复制和导出；流式与历史渲染保持一致。

### M02 持续任务与执行恢复

范围：任务、run、排队、后台执行、停止、继续、插话、检查点、重试和执行预算。

- **M02-A**：浏览器关闭、断网和重新登录后，可重新查看任务状态与最终成果；浏览器不是执行进程。
- **M02-B**：通过 worker 故障演练验证恢复；外部写入结果不确定时进入待核对状态，避免盲目重放。
- **M02-C**：插话有“已接收／已应用／未应用”反馈；取消、超时、等待用户、失败和成功有独立终态或状态。

### M03 助手、子 Agent 与工作小队

范围：默认助手、用户自建助手、角色设定、能力绑定、委派、协作与成果汇总。

- **M03-A**：助手身份与具体会话、run 分离，保留头像、说明、可用工具、知识和模型配置。
- **M03-B**：子任务能看到来源、负责人、状态、结果和费用；总任务能汇总失败与未完成部分。
- **M03-C**：内置子 Agent、外部工具服务、第三方 Agent 使用不同类型标识与权限契约，不混成同一种聊天角色。

### M04 MCP、连接器与工具中心

范围：系统／个人 MCP、工具发现、授权、健康检查、参数校验、调用记录；可扩展邮箱、日历、文档、业务系统。

- **M04-A**：用户能看见哪些连接可用、哪些需重连、哪些没有权限；授权状态和调用权限由服务端校验。
- **M04-B**：工具结果关联来源任务、参数摘要、耗时、状态和错误；密钥不进入普通日志与会话内容。
- **M04-C**：读操作与外部写操作采用明确策略，授权范围、确认内容、幂等键及执行回执能够对应。

### M05 技能与指令库

范围：提示词、SKILL.md、技能资源、工具依赖、脚本执行范围、安装、版本、共享和运行记录。

- **M05-A**：提示词预设、仅上下文型 Skill、可执行 Skill 分别展示能力和依赖。
- **M05-B**：技能版本可固定、升级、停用和回滚；任务记录实际使用的版本。
- **M05-C**：从成功任务整理技能时，用户可以预览指令、资源和所需授权，并用样例验证后发布。

### M06 个人知识库

范围：用户资料集合、解析、索引、检索、引用、更新和删除。

- **M06-A**：上传后明确展示处理中、可检索、失败及重试入口，不把“上传成功”显示为“知识已可用”。
- **M06-B**：回答引用能定位到文件和版本；具备页码的来源显示页码，其他来源显示段落、章节或原文片段。
- **M06-C**：知识源删除、更新或撤权后，新检索与缓存结果遵守新状态；已有回答保留必要的来源快照与失效提示。

### M07 项目与企业知识治理

范围：项目资料、部门知识、企业制度、公共知识发布与访问边界。

- **M07-A**：知识可见范围支持个人、指定项目成员、部门或企业；检索阶段执行权限过滤。
- **M07-B**：制度与模板有责任人、版本、生效状态和更新时间，过期资料能够下架或替换。
- **M07-C**：支持检索调试与问答评估样例；无证据、索引未就绪、权限不足和模型错误分开反馈。

### M08 文件库与成果生命周期

范围：上传文件、Agent 生成文件、文件夹、预览、搜索、收藏、版本与成果修改。

- **M08-A**：所有已发布成果进入文件库，能反查来源任务、run、创建者、输入资料和生成时间。
- **M08-B**：继续修改保留旧版本，新版本关联变更说明；用户可预览、下载和切换。
- **M08-C**：文件加入知识库是显式选择，并经过解析／索引流程；文件存储状态与知识可用状态分开。

### M09 项目空间与真实成员协作

范围：共同目标、会话、资料、成果、成员、交接和项目摘要。

- **M09-A**：项目支持所有者、编辑者、查看者等明确角色，分别限制会话、文件、知识和操作。
- **M09-B**：成员可在授权范围内接手任务，知道已有决策、当前进展、待确认项和交付位置。
- **M09-C**：外部只读分享与内部共同工作使用不同权限模型；撤销成员访问后重新校验相关资源。

### M10 记忆与上下文管理

范围：个人偏好、项目背景、长期记忆、压缩摘要、来源及纠错。

- **M10-A**：记忆可查看、修改、删除，并标识来源及作用范围。
- **M10-B**：私人记忆、项目共享背景和企业知识不交叉泄露；切换范围后上下文同步变化。
- **M10-C**：压缩与恢复后仍能追溯关键约束；用户纠正的信息有明确更新结果。

### M11 云端执行环境

范围：代码沙箱、浏览器操作、终端、目录、文件读写与结果发布。

- **M11-A**：普通 Web 用户无需安装执行依赖即可完成服务端任务。
- **M11-B**：用户可按需查看执行页面、目录、输出和错误；预览与接管入口具有一致权限。
- **M11-C**：任务环境隔离，资源配额、生命周期和文件持久化规则明确；到期前可发布需要保留的成果。

### M12 自动化与通知

范围：一次性、周期性、条件触发任务，执行历史、停用、失败处理与通知。

- **M12-A**：时区、下次运行、触发条件、授权范围和输出目的地可预览与修改。
- **M12-B**：任务有防重入、并发限制、取消、失败记录及再次运行入口。
- **M12-C**：通知携带任务链接、状态与成果；通知发送失败与任务执行失败分别记录。

### M13 多端访问与轻量体验

范围：桌面网页、窄屏、移动网页、PWA、同步、键盘操作和减少动画；可选原生客户端。

- **M13-A**：在 1366×768 等常见办公尺寸完成主要操作，侧栏与预览可收起；移动端不会挤成三列。
- **M13-B**：PDF、Office、图表等重型模块按需加载；减少动画模式生效，日常界面无需持续运行动画背景。
- **M13-C**：同一任务跨设备查看时状态一致；可选客户端不成为普通办公的前置要求。若以全端覆盖为对标目标，原生客户端需单独完成验收，不能用响应式网页冒充。

### M14 多模态与内容交付

范围：图片理解与生成、文档和表格处理、演示稿、网页、音频及模型支持的视频能力。

- **M14-A**：按所选模型和已连接工具声明能力，失败时明确指出不可用环节。
- **M14-B**：文档、表格、演示稿等产物通过实际可打开的文件验收，包含生成、预览、下载和后续修改。
- **M14-C**：音视频等长任务有异步状态、取消和预算，不占据主聊天界面的大量控制项。

### M15 模型、渠道与路由

范围：平台模型、供应商、渠道、能力、思考档位、参数、路由、失败切换、个人自带密钥与用量。

- **M15-A**：显示给用户的模型与实际供应商／路由记录可对应，切换过程可追溯。
- **M15-B**：路由能力与任务匹配，故障切换不丢失必要的工具和多模态契约。
- **M15-C**：统一管理限流、并发、重试和成本；重试后的记账以实际调用与回执为准。

### M16 企业身份、权限与审计

范围：组织与成员、企业身份源、角色、资源授权、可信设备、操作审计与数据边界。

- **M16-A**：企业登录、停用账号、移除成员及会话撤销贯穿 API 与资源访问。
- **M16-B**：组织、项目、知识、文件、工具和模型访问分别校验；多租户部署增加跨租户访问测试。
- **M16-C**：管理员变更、授权、外部写操作有审计记录；普通用户仍使用简洁主界面。

### M17 统计、预算与运营

范围：个人／团队／企业统计，调用、任务、费用、成功率、等待、耗时、模型、技能和工具；可选商业化部署再启用订阅、充值、积分与支付。

- **M17-A**：任务数、run 数、模型请求数和工具调用数分别统计；成功、失败、取消、超时、待审批口径明确。
- **M17-B**：输入、输出、缓存 Token、路由、重试和费用可追溯，部门／项目预算及导出由权限控制；启用支付时，订单、回调和入账具备幂等及对账记录。
- **M17-C**：支持大上下文请求的失败率、耗时分布与错误分类；节省工时只能标识为估算或经确认数据。

### M18 部署、运维与质量

范围：内网部署、可选依赖、配置迁移、升级、备份、可观测性与能力评测。

- **M18-A**：前端字体和关键资源能在目标网络环境加载；部署、备份、迁移和恢复有可执行说明。
- **M18-B**：任务、模型、工具、检索与通知能用关联 ID 排查；敏感内容按配置脱敏。
- **M18-C**：固定一组真实工作样例持续回归，验证权限、引用、成果可打开性和故障恢复，指标来自实测。

## 6. 怎样做到“比 LambChat 更全”

“更全”要包含已有能力的覆盖，也要验证新增能力是否形成闭环。下列是建议重点做深的方向；其中有些在现有项目中已有部分实现，不能直接宣称独有。

| 方向 | 应达到的具体结果 | 验收例子 |
|---|---|---|
| 企业知识治理 | 个人、项目、部门、企业范围统一，检索和缓存遵守权限变化 | 移除某成员后，该成员的新检索、预览和下载均失去相应访问 |
| 成果版本与来源 | 文件、来源资料、生成 run、后续修改与知识沉淀互相可追溯 | 报告 v2 能定位原任务和 v1，重新下载 v1 不受影响 |
| 成员协作 | 真实同事共同使用项目，有编辑和查看边界 | A 发起任务，授权 B 接手；C 只能查看获准成果 |
| 长任务可靠性 | 对浏览器断网、worker 重启、模型故障和工具回执缺失分别处理 | 重启后任务可恢复；已发出的业务操作不重复执行 |
| 连接器完成度 | 从连接、授权到结果交付及失败修复均有明确状态 | 邮箱凭据失效可重连，已完成工作和失败投递分开显示 |
| 技能生命周期 | 可执行资源、版本、权限、样例验证与回滚完整 | 升级技能后样例失败，可回滚并解释本次任务用了哪个版本 |
| 运营分析 | 能定位部门、项目、模型、上下文长度与错误类型 | 看出大 Token 请求失败集中在哪种模型／路由及任务阶段 |
| 低配置终端体验 | 日常操作轻量，预览和高级能力按需加载 | 在约定基准机与企业浏览器上完成实测，记录首屏与长会话表现 |

额外的性能数值应在确定目标设备、浏览器内核、网络和并发规模后设定。这里不虚构“支持多少并发”“响应多少毫秒”或“节省多少小时”。

## 7. UI 信息架构：18 个模块如何保持简洁

### 默认首页

只显示品牌、小问候、一个输入框和少量起步建议。最近工作可放进侧栏，不铺满首页。

### 主侧栏

常用入口：

- 新对话。
- 搜索。
- 个人知识库。
- 文件库。

项目与最近对话在下面按需展开。助手可以通过会话选择器或小头像入口访问，不必永远展示一整排助手状态。

### 对话过程中

- 文件和知识以输入框内的小标签引用。
- 计划与执行过程嵌在消息中，细节逐层展开。
- 需要确认时显示当前待处理卡片。
- 成果首先是可点击文件卡片；打开后出现右侧预览，关闭后恢复单列。
- 子任务、终端和浏览器执行放进同一个可切换的工作面板，避免同时堆出多个面板。

### 其他入口

技能／工具通过输入框附件菜单、斜杠菜单或“能力”面板进入；自动化通过工作空间入口或对话内创建；统计进入独立页；管理员配置只对具有权限的人显示。

个人知识库、文件库是用户明确要求的常用入口，应保留文字名称。统计需要存在，但不需要成为默认首页。

## 8. 技术取舍

如果新项目尚未固定前端技术，建议优先使用 React + TypeScript + Tailwind + shadcn/ui。理由是 DEEIX 与 LambChat 都采用 React，相关交互和现有前端资源更方便参考；PigeonAgent 的优秀交互可以重新实现。

可以使用 Streamdown 处理流式内容、Motion 实现少量状态过渡、Lucide 统一图标、Recharts 展示统计。具体版本由实施时的依赖兼容检查决定。

如果已有 Vue 工程，则可继续使用 shadcn-vue + AI Elements Vue + markstream-vue。不应仅因为参考项目使用 React 就强制重写已有工程。

后端需保持一套权威的任务、身份、权限、文件与用量模型，再为模型、MCP、浏览器和沙箱实现适配器。是否采用 Go 或 Python，取决于已有基础与执行生态；本报告不要求同时引入两个完整业务后端。

## 9. 交付顺序与完成口径

### 第一阶段：形成可用的在线工作 Agent

优先完成 M01、M02、M04、M05 的基础、M06、M08、M11、M15，以及最低必要的 M16—M18。至少跑通“提出需求 → 使用资料／工具 → 人工补充或确认 → 成果交付 → 继续修改”。

这个阶段不能对外宣称已经全面超过 LambChat。

### 第二阶段：覆盖对标基线

补齐常驻助手与小队、后台／定时任务、记忆、丰富预览、渠道通知、权限与完整运营。把 LambChat 当前版本的每项目标能力逐项映射到实现和验收，不用相似名称替代实际效果。

### 第三阶段：完成重点增强

集中完成企业知识权限、成果版本、成员协作、连接器闭环和质量运营，实施低配置终端与故障恢复测试。

### 完成一项功能所需的证据

每项能力至少有：用户入口、服务端规则、持久化、权限、错误与恢复行为、可重复的验收记录。

“有一个页面”“有一个按钮”“README 写了支持”均不能独立作为完成证明。
