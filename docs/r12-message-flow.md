# 第 12 轮：消息流重构（参考 DeepSeek Harness）+ 准备工作空间 + 本地环境置灰

本轮优先级：只做对话体验。“AI 生成文档的版本管理”方向暂停，不再投入。

参考源码：`github.com/deepseek-ai/deepseek-harness`（MIT）。读过的部分：

- `packages/client/ui-primitives/src/DisclosureRow.tsx`：24px 过程行，整行可点。
- `packages/client/ui-tool/src/client/tool/components/ToolRow.tsx`：工具单行摘要 + 展开后的 I/O 卡片，失败时显示 ExitCodeBadge。
- `packages/client/ui-chat/src/client/chat/ReasoningRow.tsx`：思考行，流式预览最新一段的首行，右侧渐隐。
- `ChatGroupSeat.tsx` + `use-process-scroll.ts`：过程分组，组体限高，自动跟随最新内容，上下边缘渐隐。
- `TurnProcessNodeView.tsx`：回合结束后折叠为“已完成，用时 …”。
- `RunningStatus.tsx`：运行中计时。

我们**没有复制代码**，只借鉴交互；视觉沿用 Workroom 自己的简洁风格。豆包截图只用来参考形态，没有仿做它的主页。

## 1. 交互规则（实现：`web/src/features/chat/Steps.tsx`）

| 元素 | 收起时 | 展开后 | 状态 |
|---|---|---|---|
| 工具行 `ToolRow`（`tool-step`） | 图标 · 名称 · 一句结果 …… 状态/耗时 › | 参数（代码类工具显示代码）+ 输出；失败时为“错误”，红色 | 运行中文字扫光；失败显示红色“失败”；退出码非 0 显示红色“退出码 N”；完成后显示真实耗时（`durationMs`） |
| 思考行 `ThinkRow`（`think-step`） | 运行中：“思考中 · N 秒”，下方是一个 7.5rem 高的小窗，随新内容自动滚到底，顶部渐隐。结束后：“已思考 N 秒 · 首行摘要” | 完整思考文本 | 秒数从模型请求开始计（`partial.startedAt`，真实时间），在本页观察到思考结束时冻结；刷新后没有测量值的只写“思考” |
| 准备工作空间（`workspace-step`） | ✓ 准备工作空间 …… 27 ms › | 会话存储 / 工作目录 / 记忆、项目文件 / 执行环境（xx · 需要时启动），逐项 ✓ 或 ! | 服务端测量的真实耗时 |
| 分组 `step-group` | 相邻的思考和工具调用（≥2 个）合成一组。运行中显示当前动作（“正在运行代码…”）；结束后显示汇总（“思考，运行代码 2 次”）…… N 步 › | 组内各行 | 运行中组体最高 min(320px, 45vh)，自动跟随最新一行；用户往上滚就停止跟随；边缘渐隐 |
| 回合（`step-chain` / `run-summary`） | 回合结束且有回答：整个过程折叠为“已完成，用时 N 秒 ›”，失败和截断以红色/灰色小字附在后面 | 全部过程 | 回合结束时自动折叠；没有回答（出错、被停止）时保持展开 |
| 运行中计时（`running-status`） | 没有任何行在显示自身进度时，底部显示“● 思考中 · N 秒” | — | 从用户消息发出算起（真实时间戳） |

详情只有一种入口：整行可点，行尾的 › 转为向下。已删除的杂项入口：

- 步骤里的“技术详情”“在工作区中打开”“在工作面板中查看”“预览 xx”（成果文件仍以文件卡片显示在回答下方）；
- 折叠时的失败行和它的“详情”按钮（失败改为在折叠行上显示“· N 步失败”，展开后该行为红色）；
- 审批卡片里“查看详情”内嵌的第二层“技术详情”（参数直接显示在详情里）；
- 错误提示、运行失败横条、凭据卡片、待核对卡片里的“技术详情”（都改为行尾 ›，或直接平铺）。

## 2. 计时数据（真实，不估算）

DTO 透出了 pi-ai 已经记录的时间：

- 用户消息 `timestamp`；
- 模型回复 `timestamp` + `durationMs`；
- 工具结果 `timestamp` + `durationMs`；
- 流式中的回复 `partial.startedAt`。

回合用时 = 最后一个模型回复或工具结果的结束时间 − 用户消息时间。旧数据没有这些字段时，只显示“已完成”，不显示用时。

## 3. 准备工作空间（服务端：`RuntimeService.createConversation`）

新建会话时（首页发送第一条消息会先建会话），在同一个事务里写入一条仅用于显示的记录 `wr.workspace`（模型看不到），内容：

- `ms`：从创建请求开始到准备完成的实测耗时，包括打开空间存储、创建会话、建工作目录、挂载记忆和项目文件、解析执行环境。
- `items`：逐项结果。失败也照实记录（`ok: false` + 原因），不隐藏。

不会启动或连接沙箱：纯聊天永远不启动，沿用第 11 轮 R2。前端把这条记录作为该会话第一个回答的第一行。

## 4. 本地环境置灰

规划是本地桌面应用上线后，命令可以访问用户自己的电脑。现在还没有实现，所以：

- 弹窗里“本地环境”保留原位，置灰（`aria-disabled`，虚线框），悬停提示“本地应用上线后可用”，点击无效。
- 会话默认偏好改为 `cloud`（`LocalExec.defaultPreference`）。第 11 轮的浏览器内执行代码仍在，只有显式设为 `local` 的会话才会用。该接口仍可用，测试也覆盖；界面已不能再选。

## 5. 测试用指令

测试模型新增 `[[think <text>]]`：回答前先输出一段思考，用来测试思考行。`WORKROOM_FIXTURE_TPS=<n>` 让测试模型按每秒 n 个 token 流式输出，只用于测试和演示。
