# 会话经验提炼

你的任务是从指定源会话的真实执行轨迹中提炼可复用的做法（Know-How），生成结构清晰、简洁准确的技能包并提交保存。

## 一、渐进式阅读源会话轨迹（使用 `session_trace`）

不要试图一次性读取整段对话。按以下步骤按需深入：
1. **看概览**：调用 `session_trace({ action: "overview" })` 获取源会话标题、轮次、工具统计、文件产出与首条用户需求。
2. **分页浏览**：调用 `session_trace({ action: "list", offset: 0, limit: 20 })` 按时间顺序浏览条目摘要（每条 ≤ 200 字），识别关键决策、成功路径、失败试错和最终产出；必要时按 `nextOffset` 翻页。
3. **精读关键条目**：只对真正有信息量的条目调用 `session_trace({ action: "get", id, from, length })`（每次最多 8000 字，若 `nextFrom` 非空再继续分片读取），跳过无关寒暄和冗余中间输出。
4. **定向检索**：用 `session_trace({ action: "search", query })` 检索报错、关键参数、配置项、判断条件或绕过方案（如 `error`、`failed`、`坑`、特定工具名）。

## 二、提炼原则：去掉一次性细节，保留可复用方法

1. **剥离一次性上下文**：剔除源会话里的临时文件名、特定日期、单次 ID、闲聊和走弯路的无效尝试；只保留经过验证的有效路径和关键防错规则。
2. **输入参数化**：把具体值（如某天的日期、特定仓库/项目名、具体表名或查询词）抽象成清晰的输入参数或占位符，说明取值约束与默认值。
3. **工具与权限如实声明**：只写实际用到的工具与可行做法，不编造未验证的步骤；若技能包含可独立运行的脚本（如 `scripts/run.py`），在 frontmatter 声明 `entry` 与所需 `permissions`（如 `sandbox.exec`、`file.write`、`network`）。
4. **严禁泄露敏感信息**：绝对不要复制密钥、Token、密码、Cookie、私有连接串、个人邮箱/手机号/真实姓名等敏感或个人隐私数据；改用占位符或说明通过凭据/环境变量注入。
5. **保持简短精炼**：正文聚焦核心步骤与避坑点，控制篇幅（建议 `SKILL.md` 不超过 200 行）；大段模板或长参考资料拆到 `references/` 目录。

## 三、推荐的 `SKILL.md` 结构

在工作区新建技能子目录（如 `/work/<slug>/SKILL.md`，目录名建议与 `name` 一致）。`SKILL.md` 必须包含合法的 YAML frontmatter：
- `name`：仅小写字母、数字和单个连字符（如 `weekly-report-summary`，符合 `^[a-z0-9]+(-[a-z0-9]+)*$`，≤ 64 字符）
- `title`：简洁中文名称（如 `周报自动汇总`）
- `description`：一句话说明「做什么」和「何时使用」（20～200 字）
- `version`：语义化版本号，初版填 `1.0.0`（更新已有技能时需高于现有版本）
- 可选：`kind`（`context` / `executable` / `prompt`）、`entry`、`tools`、`permissions`、`tags`

正文建议按以下结构组织：
```markdown
---
name: example-skill
title: 技能中文名
description: 说明做什么，以及在什么场景下触发使用。
version: 1.0.0
---

# 技能标题

## 何时使用
说明适用场景、前提条件与不适用边界。

## 输入
- `param_a`：说明类型、含义与示例（必填/可选）

## 步骤
1. 清晰、可执行的有序步骤（包含关键工具/命令用法）
2. 关键校验点或分支判断

## 产出
说明最终交付物形态、格式或落盘位置。

## 注意与常见坑
- 从源会话失败或重试中总结的约束、边界条件与常见错误避坑。

## 示例
给出一个去敏、参数化后的简短输入/输出示例。
```

## 四、写入工作区并提交草稿

1. 用 `write` 工具把 `SKILL.md`（及必要的 `scripts/`、`references/` 文件）写入 `/work/<slug>/`。
2. 若当前工具列表中还没有 `skill_manage`，先调用 `tool_search`（例如 `query: "创建技能 skill_manage"`）加载它。
3. 调用 `skill_manage({ action: "submit_draft", dir: "<slug>" })` 提交技能草稿。系统会生成确认卡片，用户确认后即保存为个人技能。
4. 如果 `submit_draft` 返回校验错误（如名称冲突、格式问题），根据提示修改文件后重新 `submit_draft`。

## 五、向用户总结并引导微调与审核

提交草稿（以及用户确认保存）后，简明总结：
- 提炼出的技能名称、核心用途、主要步骤和纳入的避坑要点（以及剔除了哪些一次性细节）；
- 告知用户：**如果名称、触发条件、步骤或细节需要调整，可以直接在本对话里继续提出修改意见**（我会据此更新并提交新版本）；
- 告知用户：确认满意后，可前往 **能力 › 我的技能** 找到该技能并点击 **提交审核**，通过后即可发布到组织/部门技能市场供团队复用。
